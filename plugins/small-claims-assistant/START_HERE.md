# START HERE

If you are using this plugin as a user, start with the **Notice of Claim intake flow**.

Do **not** start by naming scripts, JSON, or internal files. Start by asking for help with the claim itself in plain English.

## What to ask first

Use requests like these:

- `Help me fill out a BC Small Claims Notice of Claim.`
- `Start a Notice of Claim intake interview.`
- `I want to make a small claims claim in BC. Walk me through the form.`
- `I have some facts already; help me turn them into a Notice of Claim draft.`

## What happens next

The plugin should route you into the intake experience first.

That intake flow is meant to:

1. ask who the parties are
2. ask what happened
3. ask when and where it happened
4. ask how much you are claiming
5. ask what remedy you want
6. summarize what it captured and ask you to confirm it

The intake flow is the front door. It gathers the facts needed for a BC Small Claims Notice of Claim before moving to later steps.

## What not to ask first

Do not start with requests about internal mechanics such as:

- scripts
- JSON
- file paths
- renderer internals
- payloads

Those are implementation details. A normal user should not need them to begin.

## When to ask for the next step

After the intake summary is shown and you confirm the facts, then ask for the next stage.

Good next-stage requests are:

- `Prepare the draft PDF.`
- `Check whether this is ready for the PDF.`
- `Prepare the filing submission step.`

## Plain-language rule

The simplest way to use this plugin is:

1. describe your claim in plain English
2. answer the intake questions
3. confirm the summary
4. ask for the PDF or filing-preparation step

If you are unsure where to begin, use this exact request:

`Help me start a BC Small Claims Notice of Claim.`
